# 创建 Agent 引导流程

## 不替用户决定的

以下必须通过提问让用户明确，不擅自判断：
- 角色边界（干什么 / 不干什么）
- 职责具体内容
- 行为约束力度

## 引导问题清单

### 第一批：基础信息（必问）

| # | 问题 | 用途 |
|:---|:---|:---|
| 1 | 这个 agent 叫什么？（小写+连字符） | `name` 字段 |
| 2 | 一句话描述它干什么？ | `description` 字段 |
| 3 | 它的核心职责是什么？（列出 3-5 条） | system prompt 职责段 |

### 第二批：细化需求（按需问）

| # | 问题 | 用途 |
|:---|:---|:---|
| 4 | 需要限制工具白名单吗？还是全部可用？ | `tools` 字段 |
| 5 | 需要指定模型吗？（默认保持当前模型） | `model` 字段 |
| 6 | 有没有需要它知道的背景知识？（硬件/服务/路径等） | context/ 文件 |
| 7 | 有特殊的行为约束吗？（破坏性操作确认/备份等） | 行为准则段 |

### 第三批：检查确认（生成后）

| # | 检查点 |
|:---|:---|
| a | agent name 和 description 是否准确？ |
| b | 职责列表有没有遗漏或多余的？ |
| c | prompt 措辞够不够精确（少用形容词，多用可验证指令）？ |
| d | 需不需要 context/ 文件？放哪些内容？ |
| e | 工具白名单够不够用？有没有不该给的？ |

## 迭代约束

- 每次改动后，展示改动摘要（修改了哪些行/字段）
- 不一次性改太多，一个维度一个维度来
- 用户说"好了"才写入文件，之前只在对话里展示
