# Planning Plugin

pi 编码助手的任务计划管理扩展。提供**上下文注入**（避免任务偏移）+ **右上方 Overlay 卡片**（可视化进度）+ **LLM 工具 + 内联标记**（自动管理计划）。

## 功能

| 功能 | 说明 |
|------|------|
| 上下文尾部注入 | 每次 LLM 请求前，将当前计划作为 system 消息注入到消息列表末尾 |
| Overlay 卡片 | 右上方浮动面板，自带边框，宽度自适应内容，分区可独立折叠 |
| Footer 状态 | 底部状态栏显示 `📋 3/5 ⚡1` 进度概览 |
| `plan_tasks` 工具 | LLM 可调用以追加/更新/查看计划（add/update/view） |
| 强制同步 | 每轮对话前注入同步指令，确保计划领先工作而非滞后 |
| 内联标记 | LLM 在回复中写 `[√:id]` 等标记即可自动更新计划（fallback） |
| `/plan` 命令 | 查看/切换分区/模板/导出/重置 |
| 快捷键 | `Ctrl+Alt+T` 循环切换分区折叠 |
| 计划模板 | 5 套预设：审查/重构/部署/功能开发/开发迭代 |
| 计划导出 | `/plan export [路径]` 导出为 Markdown 表格 |
| 规则引擎 | 前置检查（允许 paused+completed）+ 级联暂停 |
| Upsert 语义 | 同 ID 追加时更新 name/prereqs/note，保留 status |
| 测试闭环 | guidelines + 同步消息强制"未测试不算完成" |
| 依赖方向 | 自问规则防止父/子前置标反 |
| 会话持久化 | 计划状态随 session 保存，重开会话自动恢复 |

## 任务状态

| 状态 | 符号 | 中文 | 含义 |
|------|:---:|------|------|
| `pending` | `[-]` | 未开始 | 初始状态 |
| `paused` | `[=]` | 暂停 | 阻塞/等待子任务 |
| `in_progress` | `[ing..]` | 进行中 | 当前正在执行 |
| `completed` | `[√]` | 已完成 | 正常结束 |
| `cancelled` | `[x]` | 取消 | 放弃/不再需要 |

**状态转换规则**：
- `pending → in_progress`：前置必须 `completed` 或 `paused`（不可 `pending`）
- `paused/cancelled`：依赖它的 `in_progress` 任务自动级联 `paused`
- 允许多个任务同时 `in_progress`
- 父任务（整体目标）的前置是其子任务；子任务前置是上游依赖
- 建依赖前自问：*"A 完成 B 才能开始？" → B 前置 A。 "B 都完成 A 才算完？" → A 前置 B。*
- 改动完成后未通过测试验证的任务不应标记完成

## 任务格式

```
[状态]-#ID.任务名称 前置：[...]
  ps. 可选备注
```

### 示例

```
[ing..]-#1.设计架构
  需要支持多租户
[未开始]-#2.实现核心逻辑 前置：[1]
[已完成]-#3.编写测试 前置：[2]
```

## plan_tasks 工具

### Action

| action | 职责 | 参数 |
|------|------|------|
| `add` | 追加任务（upsert：同 ID 更新） | `tasks: [{id, name, prerequisites?, note?}]` |
| `update` | 更新状态 | `changes: [{id, status}]` |
| `view` | 查看 | 无 |

> **序列调用**：需同时追加+改状态时，在同一条回复中连续调用 `add` + `update`。

### 调用示例

**追加任务**：
```json
{
  "action": "add",
  "tasks": [
    { "id": 1, "name": "分析需求" },
    { "id": 2, "name": "设计架构", "prerequisites": [1] },
    { "id": 3, "name": "编码实现", "prerequisites": [2], "note": "含单元测试" }
  ]
}
```

**更新状态**：
```json
{
  "action": "update",
  "changes": [
    { "id": 1, "status": "completed" },
    { "id": 2, "status": "in_progress" }
  ]
}
```

### Guidelines（注入给 LLM）

- 使用 plan_tasks 管理任务计划，每次状态变更后及时更新，避免任务偏移
- 新建任务用 `add`，只追加不替换
- 开始任务前用 `update` 将状态设为 in_progress
- 完成任务后立即将状态设为 completed
- 任务阻塞时设为 paused；取消时设为 cancelled
- 序列调用：同时追加+改状态时，连续调用 add + update
- 任何待解决事项都应创建为任务——包括设计讨论、技术决策、bug 分析、代码重构方案
- **改动实施后必须通过测试验证方可标记完成，未验证保持 in_progress**
- **父任务前置子任务（非反之），建依赖前自问方向**
- **对插件/项目自身的修改操作也是任务，必须创建和追踪**
- **多轮无进展的进行中任务 → 退回暂停或未开始**

## 内联标记（自动同步）

LLM 在回复中直接写标记即可自动更新计划，无需调用工具：

| 标记 | 效果 |
|------|------|
| `[√:1]` 或 `[✓:1]` | 任务 #1 → 已完成 |
| `[ing..:2]` | 任务 #2 → 进行中 |
| `[=:3]` | 任务 #3 → 暂停 |
| `[x:4]` | 任务 #4 → 取消 |

> 示例：LLM 回复 *"重构完成 [√:3]，接下来开始测试 [ing..:4]"*

## 强制同步（两阶段）

每轮用户对话分两阶段执行：

```
用户消息
  → 阶段 1（计划）：注入同步指令 → 仅 plan_tasks 可用
    → LLM 调 plan_tasks（add/update）
  → 阶段 2（执行）：恢复用户原消息 → 全部工具可用
    → LLM 正常工作
```

**阶段标记**：`---计划阶段---` / `---执行阶段---` 分别标识。

**工具屏蔽**：计划阶段通过 `tool_call` 事件 block 所有非 `plan_tasks` 工具，确保 LLM 只做计划不做执行。

**同步消息**（计划阶段注入）：
> **【强制】** 先扫描本轮对话：
> A) 新问题/需求 → add 追加
> B) 任务进展 → update 更新
> C) 两者皆有 → 序列调用 add + update
> D) 无实质性内容 → 跳过
> 改动未测试不应标记完成 | 检查依赖方向 | 计划阶段只做计划

**防环回**：两阶段各执行一次，执行阶段结束自动重置。

## Overlay 布局

```
┌──────────────────────────┐
│                          │
│📋 目标：3/5 ⚡1           │
│▼ 进行中 (1)              │
│[ing..]-#2.               │
│  设计架构                 │
│▼ 目标 (2)                │
│[-]-#4.                   │
│  编写测试                 │
│[-]-#5.                   │
│  部署上线                 │
│▶ 已完成 (2 条已折叠)     │
│                          │
└──────────────────────────┘
```

- 位置：终端右上角
- 宽度：自适应内容（最长行宽度 + 边框）
- 最大高度：终端 50%
- 计划为空时自动隐藏
- 无背景色，使用终端默认背景
- 任务名称 2 空格缩进，备注 4 空格缩进

## 上下文注入格式

```
[当前任务计划 — 共 3 条]

[ing..]-#1.分析需求
[未开始]-#2.设计架构 前置：[1]
  ps. 需支持多租户
[已完成]-#3.编码实现 前置：[2]

状态：[-]未开始 [=]暂停 [ing..]进行中 [√]已完成 [x]取消
规则：进入[进行中]需前置[已完成]或[暂停]（不可[未开始]）；前置暂停/取消→依赖任务自动暂停
```

## 设计决策

| 决策 | 理由 |
|------|------|
| 上下文用中文标签，Widget 用符号 | 模型对自然语言更鲁棒；人眼对符号扫描更快 |
| Overlay 默认 unfocused | 避免阻塞编辑器键盘输入 |
| 无显式背景色 | 使用终端默认背景，视觉上更融入 |
| 宽度自适应 | 内容多时展开，少时收缩，不浪费空间 |
| 快捷键驱动折叠 | 终端 TUI 无鼠标事件 |
| 已完成默认折叠 | 减少视觉干扰 |
| 内联标记作为工具 fallback | LLM 忘记调工具时也能自动同步 |
| store 接口模式 | index.ts 纯组装，子模块通过 getter/setter 解耦 |
| `add` 而非 `init` 追加 | `init` 全量替换浪费且危险，追加 + upsert 更安全 |
| 强制同步在前（`before_agent_start`） | 计划先于工作，而非滞后 |
| 前置允许 paused | 父任务暂停后子任务可并行执行 |
| upsert 语义 | 支持"在讨论中逐步完善任务定义" |
| 测试闭环规则 | 防止未验证的改动被标记完成 |
